## Section 2 — What's included

**Two-column feature grid:**

- **Spine for teams** — Encrypted memory with team-scoped Pods. Admin can configure retention windows. Admin cannot read content.
- **Calls** — End-to-end encrypted voice with full transcription stored only in the speakers' Spines.
- **Messages** — End-to-end encrypted threads with multimodal payloads.
- **Profiles & Sigils** — Each team member has a Sigil. The team has a verifiable shared identity.
- **Sidekick agents** — Agentic runtime per user, with team-aware memory boundaries.
- **Wallet** — Native multi-chain Wallet for value transfer between members.

---

## Section 3 — Admin posture

**Body (90 words):**
The admin role in Jokuh Business is intentionally limited. Admins can manage seats, assign Pods, set retention windows, and pull audit logs. Admins cannot read user content. Cannot impersonate. Cannot exfiltrate user Spines.

This is not a configuration we have chosen — it is an architectural property. If admins could read content, the encryption model would be broken. We chose the encryption model.

---

## Section 4 — Audit and verification

**Body (80 words):**
Each Jokuh Business deployment produces signed attestations:
- Which TEE configuration is running.
- Which model versions are in use.
- Which retention rules are applied.
- Which keys are present (without exposing them).

These attestations are produced on demand, in a format your auditors can ingest. We support standard formats and bespoke output for regulated industries.

---

## Section 5 — Onboarding

**Three steps:**

1. **Provisioning** — your admin sets up seats, Pods, and retention rules.
2. **Migration** — we help your team migrate existing context (drives, transcripts, internal docs) into encrypted Spines. We never see plaintext.
3. **Adoption** — your team runs the same workflow as before, with the substrate underneath replaced.
